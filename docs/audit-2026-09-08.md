# Project audit — 2026-09-08

Run before handing the build to the client for testing. Everything below was
checked against the repo at this commit, not inferred.

## Verdict

Safe to put in front of a test client on a **staging** hostname, with the caveats
in "Before real client data" below. No unauthenticated data exposure, no IDOR,
no committed secrets, and the production image builds, boots and serves.

## Fixed during this audit

Four vulnerable production dependencies, all now on patched majors. The full
test suite — including end-to-end flows that exercise real SMTP, argon2 hashing
and Drizzle queries — passes on the new versions.

| Package | Was | Now | Why |
|---|---|---|---|
| `drizzle-orm` | 0.40.1 | 0.45.2 | **High** — SQL injection via improperly escaped SQL identifiers |
| `nodemailer` | 6.10.1 | 10.0.1 | **High** — SMTP command injection (CRLF in transport name, `envelope.size`), header injection, TLS validation in OAuth2 token fetch |
| `argon2` | 0.31.2 | 0.45.1 | Pulled in `@mapbox/node-pre-gyp` → `tar` |
| `tar` (transitive) | 6.2.1 | *gone* | **Critical** — hardlink path traversal, arbitrary file overwrite. Dependency disappears entirely on argon2 0.45 |

Also fixed: the production Docker build did not work. `src/lib/env.ts` validates
the environment at import time and `next build` imports every route, so the
build died on `Failed to collect page data for /api/auth/verify-otp` with no
secrets in the container. The build stage now sets throwaway placeholders, while
runtime still fails fast on a genuinely missing variable. Verified by building
the image and running it against a real database.

## Before real client data

These are fine for a test run but must be settled before production use.

1. **No database backups.** `docker-compose.prod.yml` keeps Postgres in a named
   volume and nothing dumps it. Documents live in Infomaniak S3 and are outside
   this stack, but users, dossiers and the audit log are not.
2. **HSTS comes from Caddy, not the app.** Correct as designed — the app is
   served over plain HTTP in development — but it means the app must never be
   exposed without the proxy in front of it.
3. **`fiduvia.ch` still serves the client's mockup.** Deploying this app to that
   hostname replaces it. Use a staging host for testing.
4. **The seeded development accounts must not exist in production.**
   `admin@fiduvia.test` / `client@fiduvia.test` with `a-long-enough-password` are
   local fixtures (`docs/development.md`). A production database starts empty;
   create the first admin with `npm run seed:admin` and a real address.
